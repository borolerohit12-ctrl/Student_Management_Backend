# Student Management Backend

FSJP Assignment–2: Student Management REST API using Spring Boot, JWT Authentication, Spring Data JPA, Hibernate, and MySQL.

## Features
- User registration and login
- BCrypt password hashing
- JWT generation after successful login
- Protected student endpoints
- Add, list, get by ID, update, and delete students
- Request validation
- Postman collection for API testing

## Technology
- Java 17
- Spring Boot 3.5.16
- Spring Security
- Spring Data JPA / Hibernate
- MySQL
- JJWT 0.13.0
- Maven
- Postman

## Requirements
Install Java 17 or newer, Maven 3.9+, MySQL Server, and Postman.

## 1. Create the database
Open MySQL Workbench or the MySQL command line and run `database.sql`.
The application also uses `createDatabaseIfNotExist=true`, but running the SQL script makes the database/table design explicit for the assignment.

## 2. Configure database credentials
Open `src/main/resources/application.properties`.
The defaults are `root` / `root`. Change them to match your local MySQL account, or set environment variables:
- `DB_USERNAME`
- `DB_PASSWORD`

The JWT secret in `application.properties` is for local classroom practice only. Replace `JWT_SECRET` with your own long Base64-encoded secret for any non-demo deployment.

## 3. Run the project
From the project folder, run:

```bash
mvn spring-boot:run
```

The application should start on `http://localhost:8080`.

If Maven reports a dependency or compilation error, check your internet connection, Java version (`java -version`), and Maven version (`mvn -version`).

## 4. Test with Postman
Import `postman/Student_Management_API.postman_collection.json` into Postman.

Run requests in this order:
1. Register User
2. Login User
3. Add Student
4. Get All Students
5. Get Student by ID
6. Update Student
7. Delete Student

The Login request saves the JWT into the collection variable `jwtToken`. The Add Student request saves the returned ID into `studentId`. Student requests inherit the collection's Bearer Token authorization.

Sample credentials in the collection:
- Username: `rohit_test`
- Password: `Testpass123!`

Registration returns HTTP 409 if the same username already exists. This is expected on repeat runs; use a new username in the collection variable/body or keep the existing user and run Login.

## API reference

| Method | Endpoint | Purpose | Authentication |
|---|---|---|---|
| POST | `/api/auth/register` | Register user | No |
| POST | `/api/auth/login` | Login and receive JWT | No |
| POST | `/api/students` | Add student | Bearer JWT |
| GET | `/api/students` | List all students | Bearer JWT |
| GET | `/api/students/{id}` | Get student by ID | Bearer JWT |
| PUT | `/api/students/{id}` | Update student | Bearer JWT |
| DELETE | `/api/students/{id}` | Delete student | Bearer JWT |

### Register request
```json
{
  "username": "rohit_test",
  "password": "Testpass123!"
}
```

### Login response (token value is generated at runtime)
```json
{
  "token": "<JWT generated by the application>",
  "tokenType": "Bearer",
  "username": "rohit_test"
}
```

### Student request
```json
{
  "name": "Rohit Borole",
  "email": "rohit@example.com",
  "branch": "Information Technology",
  "year": 1
}
```
